# Prompt It 1.3.0

Release notes and update instructions for the reviewed 1.3.0 source.

## Changes

- Detect the installed core Side Lane skill and its actual runner/configuration;
  enumerate configured providers symmetrically from Codex or Claude, separating
  configuration, authentication/capabilities, task eligibility and authorization.

- Decompose outcomes into executable task graphs before assigning agents, with
  prerequisite acceptance, exclusive ownership and integrated evidence.
- Discover current host-local model capabilities and justify each assignment.
  Include qualified Claude candidates on the same evidence basis; retain only
  the explicitly enabled fixed `glm-5.3` route and its existing governance.
- Route provider-neutrally to the least-cost or most-efficient credible fit,
  honoring compatible explicit preferences and stated usage constraints without
  querying quotas or inventing costs. Require distinct second opinions for
  justified uncertainty, impact, disagreement risk or acceptance gates, not
  provider diversity.
- Permit bounded native read-only research helpers under runtime rules and
  separately authorized qualified external review, including documented runner
  artifacts. Generic consent never activates execute, key-backed or connector
  access. Preserve coordinator discovery, synthesis and final acceptance.
- Plan required-lane readiness explicitly. Keep routine verification and docs
  with capable staffed workers; keep tiny tasks small.
- Use one canonical skill and aligned gate semantics in Codex and Claude Code,
  with host-local tools, identities and artifact locations. The separate
  read-only and claude.ai editions retain their scope.

## Validation before publication

Run `python3 scripts/validate_public_package.py`,
`python3 -m unittest discover -s tests -v`, and skill-creator
`quick_validate.py` against the canonical skill using an existing interpreter
with PyYAML. The package validator checks both manifest versions, canonical
skill-directory resolution, matching loader blocks and reference packaging.

Exercise the first brief independently with each host's supplied inventory:
wide branching work, a tiny edit, an unavailable preferred model, required versus
optional unready lanes, explicit external review authority, and connector-only
evidence. Compare authorization and graph quality, not identical model choices.
No real paid calls, credentials or external writes are needed for these checks.
Behavioral evaluation reports belong to the release review; these instructions
do not claim that live installation or all host tests have already passed.

## Tag and release process

After explicit owner approval, inspect the intended public source commit and
validation results, prepare the reviewed source changes through the repository's
normal contribution process, and obtain any required owner merge decision.
Do not self-merge. Verify both canonical manifests remain `1.3.0` and that the
release commit contains the reviewed skill, references and loader changes.

Proposed tag: `v1.3.0`, on that approved release commit only. After explicit
publication authorization, publish the tag and release notes through the normal
release process, then verify the public tag resolves to the reviewed commit.
This document creates no tag or release and grants no publication authority.

## Existing-user update path after publication

The repository's existing tag convention is `v1.2.0`; the proposed next tag is
`v1.3.0`. A version bump alone does not refresh every installed copy. The
marketplaces continue to point at the canonical engineer plugin; the read-only
edition remains separate.

For Codex users of the configured `prompt-it` marketplace, refresh its snapshot
and reapply the engineer plugin using the currently documented commands:

```sh
codex plugin marketplace upgrade prompt-it
codex plugin add prompt-it@prompt-it
```

For Claude Code users:

```sh
claude plugin marketplace update prompt-it
claude plugin update prompt-it@prompt-it
```

Start a fresh task/session afterward and verify that the loaded engineer plugin
is 1.3.0 and includes both shared reference files. These command shapes were
checked against installed CLI help; an actual post-release upgrade has not been
performed. A pinned marketplace ref, cached older installation, or repository
vendored copy may require its owner to update that pin/reapply the installation;
do not claim all installed users update automatically.

Consumers that vendor this plugin must pin the approved public commit and its
verified content digest, regenerate their snapshot through their normal sync
tool, and run their own validation. Do not label unpublished source as an
existing public revision. Prompt it stays usable without Side Lane; early
external research requires a compatible companion with the same explicit
authorization contract (prepared alongside this change as Side Lane 0.4.0).
