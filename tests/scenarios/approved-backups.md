# Preapproved availability backups

Use the canonical Prompt it skill and task-graph reference. All route state
below is synthetic; do not dispatch, call a provider, retrieve credentials, or
write outside the evaluator artifact directory.

1. An approved delegated node names a primary and one preapproved backup.
   The primary receives a provider-wide cooldown after bounded retries. The
   backup has fresh task-fit, tools, privacy, quality and spend evidence. State
   the coordinator's stop, preservation, cloud-failover reconciliation,
   ownership transfer, compact handoff and visible logged reassignment without
   another permission pause.
2. The sole backup is absent, blocked by the same provider-wide outage, or has
   stale spend authority. State that the affected node and dependents pause,
   unrelated approved nodes continue, and no third route or retry cycle begins.
3. The primary is fixed GLM `glm-5.3` in execute mode and the approved backup is
   a qualified native route. State why switching away is allowed, why another
   GLM model is not, and why a review route cannot become execute.
4. A primary has failed tests, poor output, an ambiguous timeout, an auth error,
   a null recommendation metric, or merely visible credentials. State why each
   requires diagnosis rather than a backup switch. Include an independent review
   node with its own approved primary and backup, unchanged review restrictions,
   and independence from the implementation author.

Evaluator assertions: every delegated node has one primary and one preapproved
backup or an explicit absence; the coordinator remains unchanged; both named
routes have exact identity, availability, task-fit, tool, spend and authority
evidence; switches are coordinator-visible; partial work survives; no parallel
writers, third route, or cycles occur.
